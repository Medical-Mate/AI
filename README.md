# 진료 메이트 — AI

진료 메이트의 **AI 계층**입니다. 온톨로지, 검색, 프롬프트, 가드레일 판정, 추론 파이프라인을 다룹니다.

- 조직: `Medical-Mate` — 백엔드 · AI · 안드로이드 저장소가 영역별로 분리돼 있습니다
- 협업 규칙: **[`GIT_CONVENTION.md`](./GIT_CONVENTION.md)**

---

## 무엇을 만드나

**진료 기록에 남아 있지만 환자가 모르고 지나간 것을, 기록에 있는 것만 근거로 알려준다.**

AI 계층이 맡는 것:

| 영역 | 내용 |
|---|---|
| **온톨로지** | 부위(해부 구조) 그래프 · 유의어 · 환자 표현 |
| **검색** | 온톨로지 기반 확장 + sparse retrieval |
| **문답** | 증상 문답 · 되묻기 문항 생성 |
| **가드레일** | 답변이 경계를 지켰는지 판정하고 기록 |
| **추출** | 처방전·안내문 텍스트에서 필요한 필드만 뽑기(화이트리스트) |

설계 근거: **[`docs/ai-design.md`](./docs/ai-design.md)**

---

## 절대 지키는 선

이건 기능이 아니라 **제약**입니다. 프롬프트가 아니라 **구조로** 보장합니다.

1. **진단하지 않는다** — 온톨로지에 **병명 노드를 두지 않는다.** 축은 부위다
2. **문서에 적힌 병명은 표시 가능, AI가 추론한 병명은 절대 불가**
3. **설명문을 생성하지 않고 인용한다** — 팀에 의료인이 없으므로
   의학적 정확성을 우리가 보증하지 않는다. 우리가 보증하는 건 **"출처와 일치한다"**뿐이다

**예외 — 응급 안내는 한다.** 진단 금지에만 매달려 응급을 놓치면 그게 더 위험하다.

개인정보:

- **타인의 진료기록은 받지 않는다**
- **사진은 서버로 보내지 않는다** — 온디바이스로 텍스트만 뽑는다
- **필요한 필드만 뽑는다**(화이트리스트). PII를 찾아 지우는 방식(블랙리스트)은 쓰지 않는다

## 디렉터리

```text
docs/           설계와 제약
data/ontology/  부위 온톨로지 (nodes.csv / edges.csv)
scripts/        데이터 준비 스크립트
src/            (예정) rag · prompts · embeddings · pipeline
evals/          (예정) 평가 데이터와 평가 코드
```

커밋 scope는 위 모듈 이름을 씁니다 — `prompt` `rag` `embedding` `model` `eval` `pipeline`.
`ai`는 저장소가 이미 나타내므로 scope에 쓰지 않습니다. (`GIT_CONVENTION.md` §5)

## 시작하기

아직 실행 코드가 없습니다. 지금 있는 건 **온톨로지 시드와 설계 문서**입니다.

온톨로지를 다시 생성하려면 원본을 내려받아야 합니다(용량 때문에 저장소에 넣지 않습니다):

```bash
curl -L -o uberon-basic.obo http://purl.obolibrary.org/obo/uberon/basic.obo
python scripts/extract_uberon.py
```

자세한 내용은 [`data/ontology/README.md`](./data/ontology/README.md).
