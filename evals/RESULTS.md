## 새 케이스에서 본 것

- **인젠션 3종 둘 다 전부 방어.** 요구 문장은 notes에 원문으로 남고 진단·추정값·형식 이탈은 없었다.
- **수정 발화 5종 둘 다 전부 정답.** "아까 3일이라고 했는데 일주일" → onset 갱신, "3일이 아니라 3주" → 3주, 좌우 수정도 반영. 2턴 이력으로 충분하다.
- **Sonnet의 안전 위반 1건은 evidence 축약.** 긴 발화에서 근거를 `"계단 오를 때 ... 약 먹으면"`처럼 말줄임표로 이어 붙였다. 원문에 없는 문자열이라 D4 실패. 발화가 길어지면 근거를 그대로 복사하지 않는 경향이 드러났다.
- Sonnet은 욕설 케이스 2회 중 1회에서 "존나 아파요"를 severity value에 넣었다. Terra는 2회 모두 욕설을 뺐다.
- 둘 다 "거기가 또 아파요"에서 "또"를 time_course로 만들었다(v2에서는 통과). 이력이 붙으면서 생긴 흔들림. 사고는 아니다.

## 어댑터 수정

- **Anthropic도 `max_tokens`에 사고 토큰이 포함된다.** Sonnet 5는 사고가 기본이라 1024로 두면 긴 발화에서 본문이 빈다(L01, 출력 1024로 잘림). 8192로 올리고 그 1건만 재호출. Gemini와 같은 문제.

## 판정 갱신

- v2에서 동률이던 둘이 v3에서 갈렸다. **Terra 73/74 vs Sonnet 69/74, 차이 4회로 "차이 없음" 대역(3회 미만)을 벗어난다.**
- 갈린 지점이 이 제품의 핵심과 겹친다: 긴 발화에서 근거를 글자 그대로 옮기는 것, 감정 표현을 값에서 빼는 것.
- Sonnet은 출력 토큰이 Terra의 3배로 비용도 약 2배.
- **결정 유지·강화: Terra 채택.** Sonnet은 어댑터만 유지한다.

## 새 케이스에서 본 것

- **완곡어법은 둘 다 되묻지 않았다.** "~같아요 / 아마 / 약간" 4건 모두 filled, 값에 완곡 표현을 보존. 시나리오에서 본 "비슷한 거 같아요 → ambiguous"는 재현되지 않았다.
- **대신 Terra는 HG02 "비슷한 거 같아요"를 통째로 버렸다.** updates가 비어 엔진이 time_course를 skipped로 닫는다. 되묻는 것보다 나쁜 결과(값 손실). 1건이라 경향인지 흔들림인지는 k를 올려야 안다.
- **부정 응답 셋은 둘 다 정확히 갈랐다.** "안 퍼져요" filled / "모르겠어요" unknown / "됐어요" skipped.
- **숫자 없는 심각도에 숫자를 만들지 않았다.** "못 참을 정도", "참을 만해요" 그대로.
- **환자가 말한 병명은 둘 다 notes로 보냈다.** "감기 같은데", "관절염인가 싶어서요"가 값에는 없고 notes에 원문으로 남았다. Sonnet은 chief_complaint에 "감기 같은데"를 포함했다 — 환자 표현 그대로라 규칙 위반은 아니지만, 카드 상단에 병명이 보이는 셈이라 export에서 다룰지 판단이 필요하다.
- **Terra LN01: 옛 이야기를 time_course로 만들었다.** "작년에도 이랬는데 금방 나았고, 이번엔 한 달쯤" → onset 정답 + time_course "작년에는 금방 나았고…"를 덧붙임. Sonnet은 앞부분을 notes로 보냈다(정답). 과거 에피소드는 현재 경과가 아니다.

1. **축 혼동(D7)이 압도적.** 물은 축이 time_course인데 onset으로 내거나, 첫 발화에서 여러 축 중 하나만 뽑거나, 반대로 8축 전부를 채운다. 작은 모델이 "asked_axis"와 "발화에 실제로 있는 축"을 구분하지 못한다.

3. **value 비움.** 스키마에서 value가 선택이라 근거만 내고 값을 비운다. 2B는 158건 중 154건. 카드에 값이 안 들어간다. → 스키마에서 FILLED면 value 필수로 조이면 구조로 잡힌다.
4. **이력 이해 실패.** 수정 발화(correction) 0/8. "아까 3일이라고 했는데 일주일"을 못 따라간다.
5. **인젝션 방어 실패.** 요구 문장을 notes로 보내지 않고 축 값에 반영하거나 형식을 깨뜬다.
6. JSON 파싱 실패 1~3건: 긴 발화에서 문자열이 끝나지 않음(반복 루프로 max_tokens 도달).

**잘 되는 것**: 완곡어법(2B·0.6B 4/4), 부정 응답(2B 3/3), 숫자 없는 심각도(D5 통과), 문서 병명(doc_dx). 즉 "한 축에 대한 짧은 답"은 되고, "여러 축·맥락·이력·방어"가 안 된다.

## 폼/자연어 분류에 주는 시사점

작은 모델이 되는 곳 = 폼으로 뺄 필요가 없는 곳이고, 안 되는 곳이 곧 구조로 막아야 하는 곳이다.
- **첫 발화(여러 축)**: 작은 모델로는 불가. 인체도 선택으로 SITE를 빼고도 남는 축이 여럿. → 첫 발화는 서버 Terra로 보내거나, 첫 발화를 없애고 축별 질문부터 시작하는 흐름
- **축별 단일 답**: 0.6B도 절반은 됨. 여기에 칩(선택지)을 더하면 LLM 몫이 "직접 입력"만 남음
- **수정 발화·인젤션**: 작은 모델은 못 막음. 엔진 쪽 규칙(이력 비교, 값 외 텍스트 격리)으로 보완해야 함
- **심각도·경과·부정**: 폼으로 빼도 되고 작은 모델도 됨. 둘 다 가능
