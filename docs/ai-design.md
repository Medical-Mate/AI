# 진료 메이트 — AI 계층 설계

**AI·서빙 담당이 현재까지 정리한 상태입니다. 전부가 팀 합의는 아닙니다.**

## 이 문서를 읽는 법 — 세 등급이 섞여 있다

| 표시 | 뜻 | 바꾸려면 |
|---|---|---|
| **[팀]** | 팀 회의에서 정해진 것 | 팀 회의 |
| **[담당]** | AI 계층 안에서 담당자가 정한 것. 다른 직군에 요구가 없다 | 담당자 판단 |
| **[제안]** | 아직 아무와도 합의 안 됨. **착수 근거로 쓰지 말 것** | 협의 필요 |

표시가 없는 절은 **[담당]**으로 본다.

### 지금 등급

**[팀]**
- 주제 · 와이어프레임 · MVP 범위(고객용 단일 사용자, 관리자용은 서사에만)
- 다루는 범위: 근골격계 + 두통 (§2) — **부위 목록 세부는 아직 [제안]**

**[담당] — 바로 착수 가능**
- 절대 지키는 선 셋 (§1) — 경계 설계
- 온톨로지 구조 · 관계 5종 · 앵커 레벨 (§3)
- 검색 계층: 온톨로지 확장 + SPLADE, 경로별 인용 권한 (§4)
- 저장소는 Postgres 하나. 그래프 DB 안 씀 (§3)
- 화이트리스트 파서 규칙 (§5)

**[제안] — 협의 전이다**
- **부위 단위** — 디자이너 인체도가 먼저다. 그 그림에 온톨로지를 맞춘다 (§7)
- **API 계약** — 어디까지 AI 서버가 하고 어디부터 백엔드인가 (§7)
- **온디바이스 OCR 도입** — 안드로이드 몫. 도입 가능 여부 확인 전 (§5)
- **되묻기 문항 수·시점** — 화면 설계와 맞물린다
- SOCRATES 8축 중 실제로 몇 개를 묻나 — **축은 싸지만 묻는 UI는 안 싸다**

### 아직 확인 안 된 것

- **국가건강정보포털 라이선스** — 공공누리 제4유형(비상업+변경금지)으로 조회됐다.
  **공모전 출품이 「비상업적」인가**가 안 닫혔다 → `license.md`
- **의료인 자문 회신 전** — red flag 목록 · 성상 어휘 · 혼동 관계가 비어 있다
- **KOSTOM/KR CDI 기계 판독 여부** — 화면 검색만 되는지 파일이 있는지

## 1. 절대 지키는 선 세 개

이건 기능이 아니라 **제약**이다. 전부 프롬프트가 아니라 **구조로** 보장한다.

### ① 진단하지 않는다 — **온톨로지에 병명 노드를 아예 넣지 않는다**

"진단하지 마세요"라고 부탁하면 새어나간다. **없는 것은 오용할 수 없다.**
데이터에서 진단·질환 항목을 걸러내고, 축을 **부위(해부 구조)**로 잡는다.

### ② 문서에 적힌 병명은 표시할 수 있다. **AI가 추론한 병명은 절대 표시하지 않는다**

진단서·처방전에 적힌 병명은 **의사가 이미 확정한 것**이지 AI의 진단이 아니다.
그대로 보여주고 공식 설명을 인용하는 건 위반이 아니다. 추론은 위반이다.

### ③ 설명문을 **생성하지 않고 인용한다**

팀에 의료인이 없으므로 **의학적 정확성을 우리가 보증할 수 없다.**
질병관리청 **국가건강정보포털**(공공저작물, 자유이용) 등 공식 자료의 설명을 가져다 쓴다.
LLM은 **어떤 항목을 보여줄지 고르고 순서를 잡고 문장을 잇기만** 한다.

> 우리가 보증하는 것은 **"정확하다"가 아니라 "출처와 일치한다"**이다.
> 그리고 후자는 **기계로 검증된다.**

### 예외 — **응급 안내는 한다**

"지금 응급실 가세요"는 **진단이 아니라 안전 안내**다.
진단 금지에만 매달려 응급을 놓치게 만들면 그게 더 큰 위험이다.
red flag 목록은 **응급의학 자문**으로 채운다.

## 2. 다루는 범위

| | 확정 |
|---|---|
| **부위** | **근골격계(무릎·어깨·허리) + 두통** 두 도메인 |
| **문진 축** | **SOCRATES 8축 전부** — 부위·발병·성상·방사·수반증상·시간경과·악화완화·심각도 |
| 입력 | 환자 발화 + **인체 그림 부위 선택** + **처방전·진단서 사진** |
| 제외 | 관리자용(병원 스태프) — **서사에는 남기고 MVP에서 뺀다** |
| 제외 | 마이헬스웨이 API 연동 — **ISMS-P 요건으로 3주 내 불가.** FHIR 규격만 맞춘다 |
| 제외 | **증상 → 진료과 추천** — 감별이 필요해 진단에 걸린다 |

**범위 원칙: 부위는 좁게, 축은 전부.**
부위를 넓히면 노드·용어·설명·관계를 다 채워야 해서 비싸다.
축은 부위와 독립이고 어휘가 공통이라(욱신·조이는·찌르는…) 거의 고정비다.
**용어 30~50개가 촘촘한 게 3,000개가 비어 있는 것보다 낫다.**

### 진료과 대신 하는 것 둘

- **차트에 이미 적힌 다음 단계 전달** — "3개월 후 재방문", "타과 의뢰". **추론이 아니라 전달**
- **응급 여부 안내** — 위 ①의 예외

## 3. 데이터 구조

### 번역 방향 — **좁히지 않고 넓힌다**

입력이 차트로 확정되면서(§2) 방향이 뒤집힌다. 차트에는 **이미 정밀 용어가 적혀 있다.**

| | 방향 | 판정 |
|---|---|---|
| ~~환자 발화 → 정밀 용어~~ ("무릎이 아파요" → ACL) | 좁히기 | **하지 않는다.** 좁히는 건 **감별이고 감별은 의사 일**이다 |
| **차트 용어 → 환자가 아는 수준** ("전방십자인대 파열" → **무릎**) | **넓히기** | **이것만 한다** |

**좁히기를 버리면 설계가 크게 단순해진다.**
좁히기는 후보가 여럿이라 되묻고 판단해야 하지만, **넓히기는 `part_of`를 위로 타고 올라가면
끝나는 결정적 연산**이다. 되물을 필요가 없다.

### 어디까지 올리나 — **앵커 레벨**

`ACL → 무릎관절 인대 → 무릎관절 → 무릎 → 다리` 에서 **"무릎"에서 멈춘다.**
"다리"는 너무 넓고 "무릎관절"은 여전히 어렵다.

> **각 노드에 「환자 어휘 앵커」 표시를 둔다. 올라가다 가장 가까운 앵커에서 멈춘다.**

**그리고 앵커 집합 = 디자이너 인체도의 부위 단위다.** §7의 "디자이너가 먼저 그리고
온톨로지가 맞춘다"와 여기서 만난다. **그림에 있는 부위가 곧 환자가 아는 부위다.**

### 설명 형태 — 넓히기는 **대체가 아니라 병기**다

앵커로만 바꾸면 정보가 손실된다. 환자가 원래 알던 것보다 못해지고,
검색하거나 다음 진료에서 말할 때 쓸 말이 사라진다.

> **"전방십자인대(ACL)** — **무릎** 안쪽에 있는 **인대** 중 하나입니다"
>
> 원문 용어 **+ 앵커 부위 + `structure_type`**. 셋을 같이 낸다.

`structure_type`이 여기서 값을 낸다 — **환자는 인대와 힘줄을 구분하지 못한다**(아래 표).

### 이게 작업량을 줄인다

- **환자 표현(별칭)은 앵커 노드에만 붙인다.** 무릎·어깨 2개
- **세부 노드 38개는 "차트에서 인식"만 하면 된다** — 이름 · `structure_type` · SNOMED ID
- 즉 40개 전부에 표현 5~10개씩 붙일 필요가 없다

### 온톨로지 — 축은 부위, 관계는 다섯

`part-of`가 골격이고 나머지 넷이 실제로 답을 만든다.

| 관계 | 예 | 역할 |
|---|---|---|
| `part-of` | 전방십자인대 ⊂ 무릎관절 ⊂ 하지 | 환자 말("무릎") → 정밀 용어(ACL) 경로 |
| `laterality` | 좌 / 우 | 환자는 **"왼쪽 무릎"**이라고 말한다 |
| `structure-type` | 인대·힘줄·뼈·연골·근육 | **환자는 인대와 힘줄을 구분 못 한다.** 설명 대상 자체 |
| `adjacent-to` | ACL ↔ PCL ↔ 반월판 | "왜 MRI를 찍는가" 설명 |
| **`common-confusion`** | ACL ↔ 반월판 ↔ 슬개골 | **표준에 없다. 직접 만든다. 제품의 고유 자산** |

### 무엇을 어디에 넣는가 — **의료에서 벡터에는 함정이 있다**

`간염`/`간암`, `고혈압`/`저혈압`은 **임베딩상 가까운데 의미가 정반대**다.
짧은 용어명을 벡터화하면 반대 개념이 최상위로 올라온다. **의료에서는 사고다.**

| 데이터 | 처리 |
|---|---|
| 환자 증상 표현 · 설명문 · 질문 후보 (**긴 자연어**) | **벡터** |
| 용어명 자체 · 코드(KCD·LOINC·EDI) (**짧은 식별자**) | **사전/정확 매칭.** 벡터 금지 |
| 관계 (상위개념·인접·혼동) | **그래프** |

### 저장소 — **그래프 DB를 쓰지 않는다**

필요한 그래프 알고리즘은 셋뿐이고 전부 인접 리스트 + 코드 수십 줄로 된다.

| 쓰는 것 | 안 쓰는 것 |
|---|---|
| **LCA(최소공통조상)** — **다부위 정리**("무릎도 발목도" → 하지). ~~되물음 판단~~은 좁히기를 안 하므로 불필요 | PageRank · 커뮤니티 탐지 · 최단경로 · GNN |
| **사이클 검출** — partonomy는 DAG여야 한다. 손으로 만들면 사이클이 생긴다 | 그래프 DB 엔진 |
| **연결 성분** — `common-confusion` 혼동 클러스터 | 별도 그래프 색인 계층 |

**Postgres 하나로 통일한다.** pgvector까지 얹으면 벡터·역색인·그래프가 한 DB에 들어가고
백엔드 연계가 단순해진다. 조상 조회는 `WITH RECURSIVE`로 충분하다.

## 4. 검색 — **검색 경로가 곧 신뢰 등급이다**

두 경로를 쓰되 **도달 결과에 다른 권한**을 준다.

| 경로 | 성격 | 권한 |
|---|---|---|
| **온톨로지 확장** | 정확·통제 가능. 커버리지는 온톨로지 크기에 갇힘 | **답변에 인용 가능.** 경로가 근거로 남는다 |
| **SPLADE (한국어 기성 모델)** | 커버리지 넓음. 확장 이유를 통제 못 함 | **인용 불가.** "관련 있을 수 있음"으로 강등 → *"확실하지 않으니 의사에게 확인하세요"* |

**경계가 프롬프트가 아니라 검색 경로에서 결정된다.**

### SPLADE는 파인튜닝하지 않는다

한국어 SPLADE 기성 모델이 있다 — `yjoonjang/splade-ko-v1`,
`telepix/PIXIE-Splade-Preview`(역색인 호환). 둘 다 **범용이고 의학 특화가 아니다.**

**그런데 온톨로지가 그 도메인 적응을 대체한다.** SPLADE의 값은 *학습된* 용어 확장인데,
우리는 그 확장을 **온톨로지로 직접 제공**한다. 모델이 의학을 배울 필요가 없다.

**3주 예산 — 학습 0:** ①온톨로지 확장 + 역색인 → ②범용 SPLADE 안전망 →
③온톨로지 동의어 쿼리 주입. **의학 파인튜닝은 대회 후로.**

## 5. 되묻기 — **정답의 출처가 이 제품의 안전을 정한다**

화면 설계상 "약은 하루 몇 번 드시면 되죠?" → 오답 → 즉시 정정이 있다.
**그 "정답"을 AI가 어디서 아는가**가 전부다.

| 출처 | 판정 |
|---|---|
| 환자가 **앞에서 말했다** | **1차 출처.** 이것만으로 제품이 성립해야 한다 |
| 처방전·안내문 **사진에서 읽었다** | **보조.** 환자 말과 **대조**하는 용도 |
| 약 이름으로 **일반 지식에서 추론** ("나프록센은 보통 2회") | **금지 — 처방은 환자마다 다르다** |

### OCR은 1차 출처가 아니다 — 보조 확인이다

사진 판독을 정답의 근거로 삼으면 세 가지에 걸린다.

| 문제 | 내용 |
|---|---|
| **포맷 편차** | 처방전 서식이 병원·EMR 벤더마다 다르다. 구조화 추출의 신뢰도가 낮다 |
| **개인정보** | 처방전에 **주민등록번호**가 들어간다. 고유식별정보다. 사진을 서버·외부 LLM으로 보내면 그대로 나간다 |
| **설명 불가 표기** | "원인불명의 두통", "상세불명의 ~", "~ 의증" — 추출해도 **설명할 자료가 없다** |

**그래서 순서를 이렇게 둔다. 와이어프레임 S5가 이미 이 순서다.**

> ① 환자가 **먼저 말한다** — *"어떤 얘기 들으셨어요?"*
> ② 그 다음에 *"처방전이나 안내문 받으셨으면 사진으로 찍어주세요"*
> ③ OCR 결과는 **환자 말과 대조**한다. 일치하면 신뢰도가 오르고,
>    불일치하면 **"확인해 보세요"**로 낸다 — 어느 쪽이 맞다고 판정하지 않는다
> ④ **OCR이 실패하거나 사진이 없어도 제품이 성립한다**

### OCR 처리 방식 — **온디바이스 + 화이트리스트** (확정)

**상용 클라우드 OCR을 쓰지 않는다.** 사진이 기기를 떠나지 않는 경로가 실재한다.

| 층 | 무엇 | 막는 것 |
|---|---|---|
| **1층 · 온디바이스 OCR** | **ML Kit Text Recognition v2 한국어 모델** — `com.google.mlkit:text-recognition-korean` (또는 Play Services 판). **완전 온디바이스, 네트워크 호출 없음, 무료** | **사진이 기기 밖으로 안 나간다** |
| **2층 · 화이트리스트 파서** | OCR 텍스트에서 **필요한 필드만** 뽑아 서버로 보낸다 | **텍스트도 필요한 것만 나간다** |

### ★ 블랙리스트가 아니라 화이트리스트다

**"PII를 찾아서 지운다"(블랙리스트)로 가면 안 된다.** 놓치면 그대로 새어나가고,
**한국인 이름은 정규식으로 잡을 수 없다.**

> **필요한 필드만 뽑고 나머지는 전부 버린다.**
>
> - **뽑는 것**: 약 이름 · 용량 · 횟수 · 복용 기간 · 검사명 · 진료일자 · (선택)의료기관명
> - **애초에 추출 대상이 아닌 것**: **환자 이름 · 주민등록번호 · 주소 · 전화번호 · 의사 면허번호**

이러면 이름이 OCR 텍스트에 있어도 **서버로 가지 않는다.** 기기 메모리에만 있고 폐기된다.
사용자가 지적한 *"뒷자리는 마스킹돼도 이름과 앞자리가 남는다"* 문제가 **구조적으로 사라진다** —
뽑지 않으니까.

**추가 안전장치**: `\d{6}[-\s]?\d?` 형태(주민번호 앞자리·마스킹형)는 **매칭되면 버리는 규칙**을
따로 둔다. 진료일자와 혼동될 여지를 없앤다.

### 상용 API를 안 쓰는 이유가 하나 더 있다

**CLOVA OCR의 Document OCR은 *"개인정보/민감 정보가 포함되어 있을 수 있어
사전 신청/승인 절차 진행 후 제공"*한다.** 승인이 3주 안에 날지 불확실하고,
승인 절차 자체가 "이건 민감정보를 다루는 일"이라는 공식 신호다.
(해외 API는 리전·DPA 확인이 별건으로 붙는다.)

### 역할

| 담당 | 몫 |
|---|---|
| **안드로이드** | ML Kit 붙이기 + 촬영 가이드 UI. **역할이 하나 늘어난다** |
| **AI·서빙(본인)** | 화이트리스트 파서 규칙 + 약 이름 정규화(표준 코드 매핑) |

### 폴백 — OCR이 안 되면 직접 입력

약 이름 자동완성으로 고르게 한다. 번거롭지만 **개인정보 위험이 0**이고,
§5의 "OCR 없이도 제품이 성립한다"를 실제로 보장하는 경로다.

### 개인정보 — 그 외 대응

1. **사진을 서버로 아예 보내지 않는다** (위 1층). 기기에서 텍스트만 뽑고 사진은 폐기
2. **촬영 안내**로 필요 영역만 찍게 한다 (안드로이드 가이드 프레임)
3. **처방전 대신 「복약 안내문」·약봉투를 우선 받는다** — 약 이름·용법은 있고
   주민번호는 통상 없다. **3주 데모에서 가장 안전한 경로** (확인 필요)
4. 3주 데모에서는 **팀원 본인 것만** 쓰고 제출물에는 마스킹·합성으로 대체(§6)

### "원인불명의 두통" — 설명 불가가 아니라 **설명 대상이다**

의사는 확진 전에 증상성 진단명을 쓴다. KCD **R 코드(증상·징후·이상소견)** 계열이고,
국가건강정보포털에 설명 문서가 **없다**. 질병이 아니기 때문이다.
그리고 1차 진료에서는 확진명보다 이런 표기가 더 흔할 수 있다.

**그런데 환자는 이걸 병명으로 오해한다.** 실제 뜻은 *"아직 원인을 찾지 못했다"*이다.

> ~~설명할 자료가 없습니다~~
> → **"이건 병명이 아니라 '아직 원인 확인 전'이라는 뜻입니다"**

**표기의 뜻을 설명하는 것이 값이다.** 그리고 이건 진단이 아니라 **용어 해설**이라
경계에 걸리지 않는다. KCD 코드는 챕터 앞자리로 계열 판별이 되므로
(R = 증상·징후 / Z = 건강상태 접촉 등) **기계적으로 분기할 수 있다.**

→ 온톨로지에 **「표기 유형」 노드**를 둔다: 확진명 / 증상 표기 / 의증 / 상세불명.
각각에 **그 표기가 무슨 뜻인지**를 붙인다. 병명 설명이 아니라 **표기 해설**이다.

> ### **되묻기 문항은 출처에 앵커된 것만 생성한다. 근거가 없으면 문항을 만들지 않는다.**

### OCR 오독이 최대 리스크

용량 숫자 하나가 치명적이다(500mg ↔ 50mg). 처방전 양식은 병원마다 다르다.
**오독한 값을 "정답"으로 되물으면 환자가 맞게 알고 있는데 틀렸다고 정정당한다.**

- **읽은 것을 먼저 확인받는다** — *"처방전에서 이렇게 읽었어요, 맞나요?"*
- **신뢰도가 낮으면 그 항목으로 문항을 만들지 않는다**

## 6. 데이터 확보 — **우리가 만들지 않는다**

우리가 데이터를 만들고 설명도 만들고 평가도 하면 **순환**이다. 그 위에서 잘 도는 건
아무것도 증명하지 못한다.

| 출처 | 용도 |
|---|---|
| **Synthea** (MITRE 오픈소스, FHIR 네이티브) | 합성 진료기록. **구조를 우리가 정하지 않는다.** 단 미국 기준 |
| **팀원 본인의 실제 진료기록** 5~10건 | **"한국 차트가 실제로 어떻게 생겼는지"**를 아는 유일한 방법. 본인 데이터는 본인이 처리 가능 |
| **국가건강정보포털**(질병관리청) | 설명문 인용. 공공저작물 자유이용 + API 제공 |
| **KOSTOM** (보건의료용어표준) | 용어·코드 매핑. KCD·EDI·UMLS·SNOMED CT·LOINC 참조코드 연결이 **이미 있다** |

### 법적으로 지키는 선 넷

1. **타인의 실제 진료기록은 받지 않는다**
2. **팀원 본인 기록만 쓰고, 제출물에는 마스킹 또는 합성으로 대체한다**
3. **진단·처방을 하지 않는다** — 구조로 보장(§1)
4. **설명문은 공공저작물을 출처표시하여 인용한다** (공공누리 유형 확인 필요)

## 7. 다른 직군과의 접점

| 상대 | 무엇을 주고받나 |
|---|---|
| **백엔드** | AI 서버는 검색·조립·판정·스트리밍. 백엔드는 인증·세션·저장·**읽기 전용 웹링크 발급** |
| **안드로이드** | 사진 업로드 · 음성 입력 · 대화 화면. **진료 직후 알림**이 캡처 시점을 만든다 |
| **디자이너** | 인체 그림 부위 선택 UI가 **온톨로지의 입력 표면**이다. 요약 카드 · 읽기 전용 웹링크 |

### 부위 단위는 **디자이너가 먼저 그리고, 온톨로지가 거기 맞춘다**

순서를 뒤집지 않는다. 이유 셋:

- **빼는 게 삭제가 아니라 깊이 조절이다.** partonomy는 계층이라 하위를 접으면 상위로 흡수된다.
  데이터는 두고 노출 깊이만 조절하면 되므로 **되돌리는 비용이 거의 0이다**
- 그림은 자연히 **사람이 인지하는 단위**로 나뉜다. 그게 곧 환자 언어 단위이고,
  온톨로지에서 가장 어려운 "무엇을 노드로 둘 것인가"를 그림이 정해 준다
- 해부학적으로 안 맞는 단위가 나와도 문제가 아니다 — "허벅지 앞쪽" 같은 일상 구분은
  **환자가 실제로 쓰는 말**이므로 별칭으로 붙인다.
  **디자이너 단위 = 환자 표현 계층, KOSTOM 단위 = 정밀 용어 계층.** 둘을 잇는 게 원래 할 일이다

### 재현성 — 응답에 반드시 박을 것

같은 질문에 다른 답이 나올 때 원인을 못 찾으면 디버깅이 불가능하다.
**프롬프트 버전 · 모델 ID · 온톨로지 스냅샷 버전**을 응답에 넣는다.

### 판정 로그

질의 → 확장된 토큰 → 도달 노드 → **경로 종류(온톨로지 / SPLADE)** → 인용 허용 여부.
이게 경계 준수의 감사 기록이 된다.

## 8. 제출물에 정직하게 쓸 것

숨기면 심사에서 먼저 발견된다. **밝히는 편이 「실현가능성」에 유리하다.**

- **의학적 타당성을 우리가 보증하지 않는다.** 출처가 보증하고, 우리는 출처와의 일치만 보증한다
- **실제 의료 현장 검증을 하지 못했다.** 팀에 의료인이 없다 (자문은 받았다)
- **마이헬스웨이 연동은 범위 밖이다** — ISMS-P 요건. 대신 국가표준 **FHIR 규격**에 맞춰 설계
- 합성 데이터는 미국 기준이고, 팀원 실기록으로 보정했다
- **자문은 「자문」이지 「감수」가 아니다.** "검증 완료"라고 쓰지 않는다

### 「확장성」에 쓸 카드

관리자용·약국 처방·결제는 **"할 수 있었는데 3주라서 안 한 것"**으로 제시한다.
**버릴 것을 먼저 정했다는 게 심사에서 성숙도로 읽힌다.**
